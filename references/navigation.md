# Course orientation and visible progress

Use this reference for a course opening, continuation, route change or progress request. Show the arrangement and location to the learner. A saved record alone does not show this information.

Use only route metadata, permitted lesson text, learner records and the current learner packet for navigation. Do not open teacher answers, future packets, outcomes or annual disclosures to fill a progress display.

## At the course opening

Before the first lesson, give a short orientation in the learner's language. Include the purpose, main phases, selected route, learning rhythm and starting point. Then teach the first permitted small part in the same reply. Do not require an acknowledgment of the plan. Do not test terms that you only named in the orientation.

For a general systematic request, use the main route. A request that includes ETFs or other products does not by itself select product-first study. Use product-first when the learner selects that priority. Explain the selected alternative without requiring unrelated product modules or Chan study.

Use [the roadmap](roadmap.md) and [catalog](../assets/course-catalog.json) for structure. The main library has 20 modules, 80 units and 160 starting parts. These are library totals, not completion evidence or a mandatory total for each alternative route. The default overview includes all six phases:

| Main phase | Scope | Learner-facing purpose |
| --- | --- | --- |
| 1 | M01–M05 | 交易基础：买到什么、怎样成交、费用风险和信息筛选 |
| 2 | M06–M08 | 行情、K线与日本蜡烛图：先读数，再理解形态 |
| 3 | M09–M10 | 趋势、量价和规则：把观察接到条件、行动与验证 |
| 4 | M11–M12 | 缠论基础：从构件到关系，分清结构和确认时机 |
| 5 | M13–M14 | 退出管理、连续模拟与复盘 |
| 6 | M15–M20 | 产品全景、所选产品机制与完整交易训练 |

Identify the [56-lesson Chan-book route](chan-book/full-course.md) as separate depth study. Identify volume-price practice as a practice branch with its own steps. These branches are not extra main modules or evidence that the learner finished them. For a short opening, use the six-row overview or a small arrow diagram; link the detailed map for expansion. Do not teach every later definition at once.

If a learner starts with ETFs, show rights introduction → missing common foundations → ETF mechanism → four-step practice. For LOF, CB or other listed funds, select the corresponding mechanism and track. Do not call this a completed main-course sequence. For the book, show its prerequisites, morphology, dynamics, operations, historical cases and assessment, using its actual course list. Explain missing prerequisites before their questions.

If the learner asks only for a course arrangement, give that arrangement without starting a compulsory quiz. If the learner asks only for a definition, do not force an opening syllabus.

## At a new part

First give any pending [response feedback](lesson-sequence.md#after-response). Respect a requested hint, retry, pause or feedback decline. Then, before new teaching, show a compact position line. Include the active phase or branch, Chinese module/topic and local part or step position and total when known. Explain the connection to this next topic. Do not substitute a code alone for a useful location.

Find the local position from the catalog's ordered units and parts, not from the digits in an identifier alone. Use the book's full-course order for book lessons and the selected run's packet sequence for practice. Do not force book lessons or practice steps into the main module's part total.

A position describes where this reply is located. It does not mean all earlier parts were taught, reviewed or mastered. If history is incomplete, say that completed scope is unknown. Do not turn a cursor into a completed percentage. Give an exact completed count only when the actual history establishes its scope and items. A planned route can have optional branches; name the chosen scope before giving a denominator. If that scope changes, explain the new basis.

For the general route, the position can look like this:

> 当前位置：K线与蜡烛图阶段 → 第7模块“K线及价格表示” → 本模块第2/8小段：四价与盘中路径。前一小段的影线计算已讲评；更早课程的完成量暂未核对。

This is an illustration, not a fixed record for a learner. Use actual state and natural wording. Do not repeat the full roadmap at every turn. A same-question hint or retry keeps its location. A temporary lookup keeps the main cursor; give a short return reminder when there is a main lesson to return to. For a prerequisite detour, identify the missing foundation and where the course will resume.

## At a boundary, pause or progress request

Give a short checkpoint at a module or stage end, pause, session return or route change. Also give it when the learner asks about progress. Include:

- The active route and current location.
- The scope actually taught, with the evidence available.
- Responses already reviewed and items still untested, pending or needing another explanation.
- The next part and why it follows. At a pause, give it as the next planned action; do not start it.

Keep instruction, feedback and independent understanding different. A correct answer, a worked solution, a hint and an untested explanation are different evidence. Do not call a module mastered because its last page is open. Do not give a completion date or fixed learning duration without a basis.

For an older record with only a cursor, give the known location and say that historical completion needs checking. Show a short route reminder if no earlier orientation is established. Do not restart the course or require the learner to copy old answers. If a missing question prevents grading, ask for that question before dependent continuation; still explain the known course location.

## Display records

Use the conversation for actual display evidence. At a useful saved checkpoint, the optional `navigation_history` list can contain `kind`, `scope`, `location` and `evidence`. Use `orientation`, `position` or `checkpoint` for `kind`. Record only the message actually shown, not a planned opening. Keep the main cursor, separate book/track state, original skill version, responses, instruction and exposure history.

An older record needs no forced migration. If this list is missing, add an empty list only when a new record is necessary. An empty or missing list establishes neither a previous orientation nor course completion. An orientation is not concept instruction in `teaching_history`. Do not write to the installed skill for learner state. A file write after every position line is not required.

Honor an explicit request to hide routine progress lines or show less navigation. Keep the underlying evidence and answer gates. Show the requested progress when the learner asks again.
